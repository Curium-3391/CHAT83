# CHAT83 v0.6.0 — Gemini on the Original TI-83 Plus

**Release date:** 2026-10-23  
**Status:** First public hardware-tested release; still experimental on hardware beyond the original TI-83 Plus  
**Source:** Curium-3391/CHAT83

> A working Gemini AI chat terminal for an original TI-83 Plus, using its
> 2.5 mm TI Link port, Arduino Uno and a Windows Python bridge.

## Highlights

- **Real Gemini API conversations:** bidirectional TI Link communication,
  multi-turn questions and answers, streaming updates and SQLite history were
  observed on physical TI-83 Plus hardware.
- **New chat layout:** `GEMINI>` is its own 12-character history row, and
  generated answer rows now use **all 12 characters**, not `PC: ` plus
  eight more characters. Legacy records and offline demo replies are preserved.
- **Input editor:** clear all 49 bytes of the question buffer before entering
  a new message, fixing phantom text from the previous question that could
  not be deleted or navigated.
- **Turnaround improvement:** finish drawing the calculator's waiting/history
  screen before sending Q so incoming data is not blocked by an LCD redraw.
  The host's 250ms reply delay is still the recommended tested setting.
- **Reconnect resilience:** a retry (`R seq CRC8`) from a previous PC session
  no longer terminates the Python bridge; it is ignored with a
  `[RESYNC NEEDED]` warning so a new `S` can recover persisted history.
- **Optional readability and diagnostic controls:** `--word-wrap` formats
  streamed English at word boundaries, including full-width Gemini rows;
  `--batch-pause-ms 150` is available to investigate rare 16-byte
  batch-boundary history FETCH stalls. Both are **off by default**.
- **Maintainable test suite:** Python/SQLite integration tests, mocked Gemini,
  Z80 program/App emulator tests, Uno firmware compile and simulated TI Link
  electrical handshakes.

## Hardware and compatibility

| Component | Requirement |
| --- | --- |
| Calculator | **Original TI-83 Plus**; not the TI-83 Plus SE or TI-84 Plus |
| TI software | `CHAT83.8xk` (signed Flash App), or `C83V5.8xp` (Asm program) |
| Adapter | Arduino Uno, bundled custom CHAT83 Uno v0.5 sketch |
| 2.5 mm TI Link wiring | TIP → Uno **D3**, RING → Uno **D6**, sleeve → GND |
| USB to host | Windows COM port (observed as COM2), 115200 baud |
| Host | Python 3, `pyserial`, official `google-genai` SDK |
| Existing history | Reuse SQLite `chat83.sqlite3` file; **do not delete it** |

The bundled Uno firmware is **not** a TiLP adapter. If the same Arduino is
used to transfer calculator files, temporarily flash a compatible
`serial2ti83` sketch with its TIP/RING pin assignment adapted to D3/D6,
close TiLP and re-flash the bundled CHAT83 sketch before chatting. Unplug
the calculator's 2.5 mm Link cable before reflashing to avoid bus contention.
Follow [full hardware instructions](../v05-integrated-terminal.md).

## Quick start — Windows PowerShell

Extract the CI-built Windows kit to a folder such as
`$HOME\Downloads\CHAT83_v05`. The kit still uses v0.5 filenames because
the Link protocol remains compatible with v0.5.

```powershell
py -m pip install -r "$HOME\Downloads\CHAT83_v05\requirements-v05-gemini.txt"
```

Create a Gemini key at [Google AI Studio](https://aistudio.google.com/app/apikey)
and set **GEMINI_API_KEY** in Windows *user environment variables*. Close
and reopen PowerShell so it picks up the value. **Do not paste the key in
chat, GitHub, screenshots, ZIPs, scripts or logs**.

```powershell
py "$HOME\Downloads\CHAT83_v05\bridge_v05.py" --port COM2 --provider gemini --model gemini-3.5-flash-lite --gap-ms 35 --reply-delay-ms 250
```

Start the bridge first, then open the App from the TI-83 Plus `APPS` menu,
enter a short question and send with ENTER. The resulting history should
look approximately like this, as separate 12-column rows:

```text
YOU: HELLO
GEMINI>
HELLO WORLD!
```

To try the optional word wrap while keeping tested Link parameters, append
`--word-wrap`. To diagnose a rare 81-byte `FETCH OLDER` TX failure,
keep the same parameters and separately try `--batch-pause-ms 150`;
do not change reply delay and inter-byte gap simultaneously.

## Upgrading from the previous test kits

1. Back up `chat83.sqlite3` and the last-working `bridge_v05.py`.
2. Install the new `CHAT83.8xk` or `C83V5.8xp` on the calculator;
   **the question-editor fix requires updating the Z80 binary**.
3. Replace the host Python files with the release kit's versions.
4. Keep the existing Uno wiring and bundled CHAT83 Uno firmware.
5. Use the known-good 35ms gap and 250ms reply delay first.

Older `PC:` lines in SQLite are intentionally not rewritten; only new
Gemini answers use `GEMINI>`. The message text sent back to Gemini
contains the actual assistant content, not the visual `GEMINI>` label.

## Known limitations

- **Not broadly validated:** initial real-device testing used one original
  TI-83 Plus and Arduino Uno. Real-world timing may vary with cabling,
  state, power-cycle and long sessions.
- **Interrupted FETCH on power-cycle:** if a Bridge restart loses its
  outstanding reply, the TI may send an orphaned `R`. The bridge now
  stays online, but the calculator must enter LINK ERROR and use MODE for
  SYNC, or fully exit and relaunch the App. An automatic scroll-position
  restore is not implemented.
- **Rare `FETCH OLDER` stalls:** a TX_WAIT_ACK timeout was previously
  reported on an 81-byte history frame at batch offset 16; its physical
  root cause is unproven. The optional batch pause is only a diagnostic.
- **Timing:** 35ms inter-byte gap and 250ms host turnaround are the
  tested conservative settings. Reducing delay to zero was **not**
  proven safe on real hardware.
- **Text:** fixed 12-character ASCII rows; non-ASCII Gemini text may be
  transliterated or replaced with `?`. No raw Unicode fonts are included.
- **Credentials/network:** Gemini requires Internet and a user-supplied
  API key, subject to Google's model availability, rates and billing.
  The demo provider works offline.
